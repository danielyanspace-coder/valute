# Аудит безопасности Crypto IX

Редакция от 10.10.2026. Проверены: код сервера и Mini App, бот, админка, денежная логика, зависимости, скрипт установки сервера, организационные риски.

## Итог

Код в хорошем состоянии: SQL-инъекций нет, подпись Telegram проверяется правильно, балансы меняются только внутри транзакций, чужие заявки недоступны. Главные риски не в коде, а в **ключах и устройствах**: токен бота, пароль админки, компьютер с TronLink, аккаунт DuckDNS.

## Что проверено и в порядке

| Область | Результат |
|---|---|
| Вход в Mini App | Подпись `initData` проверяется HMAC-SHA256 по токену бота, сравнение за постоянное время, срок жизни 24 часа |
| Двойное списание | Проверка баланса и списание в одной транзакции `BEGIN IMMEDIATE`, Node однопоточный: гонок нет. Повторные нажатия гасятся `requestId` |
| Смена статусов сделок | `UPDATE ... WHERE status = :from`: два одновременных клика не пройдут оба |
| Чужие данные (IDOR) | Все заявки, выводы, заказы, чеки читаются только через `getForUser` / `user_id` |
| SQL-инъекции | Везде подготовленные запросы с параметрами; в текст SQL попадают только имена колонок из кода |
| Коды чеков | 12 символов криптостойкого генератора (~70 бит), подбор невозможен |
| Пополнения | Зачисление только после необратимого блока, проверка контракта USDT и получателя по блокчейну, данные индекса не доверяются |
| Вывод USDT | Хэш проверяется в блокчейне, один хэш не закроет две заявки, адрес получателя проверяется по санкционным спискам |
| XSS | React экранирует вывод; единственный HTML от пользователя (рассылки) вводит только админ, теги ограничены |
| Пароль админки | 192 бита случайности, сравнение за постоянное время |
| Зависимости | `npm audit --omit=dev`: 0 уязвимостей в работающем сервере. 3 high только в инструментах сборки (braces), на сервер не влияют |

## Исправлено в этом аудите

1. **Ограничение частоты запросов** (`@fastify/rate-limit`): 600/мин на IP в целом, 120/мин на админку, 60/мин на генерацию картинок чеков (защита одного ядра от DoS), 30/мин на поиск по username (нельзя перебрать базу пользователей).
2. **Заголовки защиты**: CSP (скрипты только свои и telegram.org), `frame-ancestors` (Mini App встраивается только в Telegram, админка никуда), `nosniff`, `no-referrer`, HSTS, `no-store` для API.
3. **CORS убран**: API работает только со своего домена.
4. **Сервер слушает только 127.0.0.1**: снаружи доступен только через Caddy с HTTPS, даже если файрвол отключат.
5. **Оповещения в Telegram администратору**: вход в админку с нового IP и 10 неверных паролей за 15 минут.
6. **Защита от ошибки настройки**: сервер не стартует с `ALLOW_DEV_AUTH=true` в боевом режиме (иначе любой вошёл бы без Telegram).
7. **Сервер**: fail2ban (бан после 5 неверных паролей SSH), автоматические обновления безопасности, служба изолирована systemd (`ProtectSystem`, `PrivateTmp`, `NoNewPrivileges` и др.).

## Что сделать владельцу: по убыванию важности

### Критично
1. **Перевыпустить токен бота** (`/revoke` в BotFather) и вписать новый в `/opt/cryptoix/.env`. Токен светился в чате. **Токен бота = ключ ко всем аккаунтам**: им можно подписать вход в Mini App от имени любого пользователя и вывести его деньги. Никому не пересылать.
2. **Компьютер с TronLink.** На нём лежат все деньги пользователей. Отдельный профиль браузера только для TronLink, никаких «кряков», расширений и программ из чатов. На адресах пополнения держать только рабочий остаток, крупные суммы переводить на холодный кошелёк (лучше аппаратный, Ledger).
3. **2FA на аккаунте, через который входишь в DuckDNS** (Google/GitHub/X). Если его угонят, домен перенаправят на фальшивый сайт и соберут входы пользователей и пароль админки.

### Важно
4. **Пароль админки** хранить в менеджере паролей, не в заметках и чатах. Входить только со своих устройств. Пришло оповещение о входе с чужого IP: сразу сменить `ADMIN_TOKEN` (`openssl rand -hex 24`) и перезапустить службу.
5. **SSH по ключу вместо пароля root.** Пароль от хостинга мог уйти в почту и чаты. Когда будет время: создать ключ на Windows (`ssh-keygen`), добавить на сервер и отключить вход по паролю (`PasswordAuthentication no`). До этого пароль root должен быть длинным и уникальным.
6. **Копии базы вне сервера.** Раз в неделю скачивать свежий файл из `/var/backups/cryptoix` (WinSCP). Без копии смерть сервера = потеря всех балансов.
7. **Claude на сервере** работает от root и видит все ключи. После установки выйти из аккаунта (`claude /logout`) или удалить (`rm -rf ~/.local/bin/claude ~/.claude*`).

### Процессы (мошенничество пользователей)
8. Перед «Подтвердить вручную», «Принять корректировку» и зачислением неопознанных пополнений всегда проверять факт на площадке или в блокчейне. Слова клиента не доказательство.
9. Ручные корректировки баланса и теневые заморозки видны в журнале: просматривать его раз в день.
10. Следить за «Больше всех выводят» в статистике: резкий рост одного аккаунта бывает признаком угона или схемы.

## Остаточные риски (принимаются осознанно)
- `initData` действительна 24 часа: украденная из устройства пользователя даёт доступ к его аккаунту на этот срок. Telegram рекомендует такой порядок, уменьшение ломает долгие сессии.
- Пароль админки один на всех операторов. Когда появятся операторы, нужен вход каждого под своим аккаунтом (через Telegram Login) и журнал по людям.
- Бесплатный DuckDNS: при угоне аккаунта или закрытии сервиса нужен быстрый переход на свой домен (10 минут, см. `docs/DEPLOY.md`).
